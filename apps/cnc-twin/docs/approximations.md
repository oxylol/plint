# Approximations

Every approximation the simulator makes, what it does to a result, how large the error can be and what that bound rests on, collected from the model documentation, the validation results and the performance measurements. Generated by `bin/tsafe python -m cnctwin.docs_tools approximations` (cnctwin/docs_tools.py); do not edit it by hand: change the source documents and run the command again. The method and the documents whose structure did not match are at the end.

Rows: 395 statements of the model docs (238 with an error expression), 2 scope decisions, 15 validated quantities, 15 performance items. The table is one table split into one section per domain (the same columns throughout), so that the run report can show the sections of the domains a run used.

How to read it: *approximation* is what the model does instead of the full physics; *consequence* what that does to a result; *error bound* the error expressions the source states; *evidence* what the bound rests on (validation case, convergence/test, literature, estimate); *source* the document and section to read for the whole statement. Cells are clipped; "not stated" means the source statement does not say it. Validation rows give the median and 90th percentile of the absolute relative error over the independent cases of validation/results/*.json, as written by the last `twin validate`.

## Method (how this file is generated)

Sections collected from a model doc: every heading (section number stripped) that matches one of these patterns (case-insensitive), and every section below it:

* assumptions: `\bassumptions?\b`
* limitations: `\blimitations?\b or \bknown gaps\b or \bopen problems\b`
* validity: `\bvalidity\b or \bvalid\b`
* error bounds: `(?<!location )\berror\b or \berror bounds?\b or \baccuracy\b or \bexactness\b or \btolerances\b`
* approximations: `\bapproximations?\b or \bsimplifications?\b`
* consequences: `\bconsequences?\b`
* validation and verification: `\bvalidation\b or \bverification\b`

Each collected section is split into statements: a bullet with its continuation lines (nested bullets joined to it), a table row, or a paragraph; code blocks are skipped. Columns: for a table row by its header (consequence, validity, error, basis/how established/source, else the first column is the approximation); for a bullet or paragraph the first sentence is the approximation, the text after 'Consequence:' (else the following sentences) the consequence. The error bound is the table's error column, else the clauses with an error expression (a percentage, +-, <=, a factor, 1e-9, within, up to, exact, order of magnitude, ulp). Evidence classes: validation case (the validation suite, its quantities or case ids), convergence/test (convergence, refinement, a test against an exact, analytic, closed-form or reference solution), literature (a db/bibliography key, an author-year citation, a standard, catalogue, handbook, manual), estimate (est, estimated, assumed, typical, judgement).

Statements outside those sections are collected when they start with a label (pattern `^(?:\*\*)?(?:validity(?: and error)? or errors? or error bounds? or accuracy or assumptions? or limitations? or limits or approximations? or consequences?)(?:\*\*)?\s*:`, case-insensitive), such as 'Validity:' or 'Error:'.
