## Approximation sections (docs/approximations.md)

Every model doc has at least one section that docs/approximations.md collects.

## Rules

* **equations**: at least 3 equation lines: an '=' (not '==', '<=', '>=', '=>') with an operator or a function (+ - * / ^ sqrt exp ln log sin cos tan atan min max sum) beside it, in inline code, an untagged or math code block, or plain text.
* **parameters and sources**: a parameters / settings / constants / coefficients heading whose section names sources (a table column source/src/basis, src, est, db/models/<file>.yaml, db/bibliography, a bibliography key), or any table with a source column.
* **assumptions**: a heading with assumption(s), decisions or simplification(s).
* **validity range**: a heading with validity / valid, or a table column validity / valid / range.
* **error bound**: a heading with error / error bound(s) / accuracy / exactness / tolerances, or a table column error / accuracy / bound.
* **references**: a heading starting with references / bibliography / literature, with text below it.
* **text only** for parameters and sources: a line (outside code) matching `db/models/\S+ or \bsrc:\s*est\b`.
* **text only** for assumptions: a line (outside code) matching `^\s*(?:[*-]\s+)?(?:\*\*)?assumptions?\b`.
* **text only** for validity range: a line (outside code) matching `\bvalidity\b or \bvalid (?:for or within or when or while or up to or in or above or below or only or range or between)\b`.
* **text only** for error bound: a line (outside code) matching `\berror bounds?\b or \berrors? (?:of or below or within or is or are or < or <= or ~ or about or up to)\b or \baccurate to\b or \bwithin \d`.
* **text only** for references: a line (outside code) matching `^\s*(?:\*\*)?references?(?:\*\*)?\s*:\s*\S`.
* Section numbers (`10.`, `2.3`) are stripped from headings before matching; matching is case-insensitive; text inside fenced code blocks is not a heading.
